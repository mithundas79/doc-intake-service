# doc-intake-service

**A document intake service: native Tesseract OCR + a trained document-type
classifier + deterministic accounting rules, behind a FastAPI backend with a
React front-end.**

Upload a scanned invoice, receipt, statement or contract. The Python backend
reads it with OCR, a **trained classifier** names the document type with a
confidence, field extraction pulls out vendor / number / dates / amounts, and
the rule layer decides the only thing that matters: does this document file
itself, or does a person look at it first.

```
 React UI ──upload──▶ FastAPI ─▶ Tesseract OCR ─▶ extract fields ─▶ trained classifier
                         │                                               │
                         ◀──────────── rules decide ◀────────────────────┘
                         │
              verdict: file / review  +  audit.jsonl
```

This is the full-stack sibling of two other repos:

- [doc-intake](https://github.com/mithundas79/doc-intake) — the zero-dependency
  TypeScript core: same rules, browser OCR, no server, no model
- [filing-agent](https://github.com/mithundas79/filing-agent) — an LLM
  tool-calling agent that classifies documents under deterministic validation

Same design conviction in all three: **parsers, models and LLMs propose;
deterministic rules decide.** Here the classifier must also state its
confidence, and low confidence is not rounded up — it becomes a failing rule
and a person looks.

## ⚠️ What this is, honestly

**This is a demo system.** Read this before judging it against your shoebox
of receipts:

- **Do not expect every document to work.** The field extraction is
  line-based English-first heuristics; unusual layouts will land in review —
  by design, that is the safe outcome.
- **The classifier is demo-trained.** It learns from a *synthetic corpus*
  generated by `training/generate_corpus.py` — fictional vendors, generated
  wording. It scores a suspiciously perfect 100% on its held-out set
  *because* the test documents share a generator with the training ones.
  That number verifies the pipeline; it does not predict real-world accuracy.
- **Production needs enhancement**: real labelled documents and re-training,
  image pre-processing (deskew, denoise, phone-photo handling), durable
  duplicate memory and audit storage, authentication, and a review queue UI.
  The committed `model/metrics.json` says all of this next to the numbers.

## Prerequisites

| Requirement | Windows | macOS | Debian/Ubuntu |
|---|---|---|---|
| Python 3.10+ | [python.org](https://www.python.org/downloads/) | `brew install python` | `apt install python3 python3-venv` |
| Node 18+ (UI only) | [nodejs.org](https://nodejs.org) | `brew install node` | `apt install nodejs npm` |
| **Native Tesseract 5** | `choco install tesseract` or the [UB Mannheim installer](https://github.com/UB-Mannheim/tesseract/wiki) | `brew install tesseract` | `apt install tesseract-ocr` |

Verify Tesseract is on your PATH before anything else:

```bash
tesseract --version    # should print 5.x
```

If Python can't find it later, either add its folder to PATH or set
`pytesseract.pytesseract.tesseract_cmd` — see Troubleshooting.

## Quickstart

**1. Backend** (from the repo root):

```bash
python -m venv .venv
# Windows:            .venv\Scripts\activate
# macOS/Linux:        source .venv/bin/activate
pip install -r server/requirements-dev.txt
```

**2. Train the model** (one-time, ~10 seconds, fully offline):

```bash
python training/generate_corpus.py
python training/train.py
```

This writes `server/doc_intake_service/model/model.joblib` and a
`metrics.json` whose honesty note travels with the model — the API serves it
on `/api/health` and the UI displays it.

**3. Run the tests, then the server:**

```bash
cd server
python -m pytest        # 12 tests
python -m uvicorn doc_intake_service.app:app --port 8000
```

**4. UI** (second terminal):

```bash
cd ui
npm ci
npm run dev             # http://localhost:5173  (proxies /api to :8000)
```

Open the page, upload a PNG/JPG scan — or a `.txt` file to try the pipeline
before installing Tesseract at all.

## API

| Route | What it does |
|---|---|
| `GET /api/health` | Model presence + the model's own honesty note |
| `POST /api/documents` | Multipart upload (image or .txt, ≤8 MB) → full result: record, prediction with confidence and runner-up labels, rule checks, verdict |
| `GET /api/documents` | Everything processed this run (decisions only, not document bodies) |

Every decision is appended to `data/audit.jsonl` — bodies excluded, hashes
included, so the log records decisions without becoming a copy of your
paperwork.

## The rule layer

1. Vendor identified
2. Document number found — without one, de-duplication is unsafe
3. Date read — a posting date must never be guessed
4. Subtotal + tax = total
5. Line items sum to the subtotal
6. Not a duplicate — vendor + number + amount, across the server session
7. **Document type confident** — the classifier's confidence below 0.7 is a
   failing rule, not a rounding opportunity

Any failure ⇒ verdict `review`. A held-for-review document is the system
working, not failing.

## Training your own

`training/generate_corpus.py` is deliberately a *generator*, not a data dump:
the corpus is reproducible and inspectable, and swapping in your own labelled
documents is a file-format exercise (JSONL of `{"label": ..., "text": ...}`).
Re-run `train.py` and the new model and metrics drop into place. The
TF-IDF + logistic-regression pipeline was chosen because it installs in
seconds on every platform; the training interface stays the same if you
replace it with a neural model once you have real data that justifies one.

## Troubleshooting

- **`TesseractNotFoundError`** — the native binary is not on PATH. Windows:
  the default install location is `C:\Program Files\Tesseract-OCR`; add it to
  PATH, or set it in code:
  `pytesseract.pytesseract.tesseract_cmd = r"C:\Program Files\Tesseract-OCR\tesseract.exe"`.
- **`503 trained model missing`** — you skipped step 2; run the two training
  scripts.
- **UI says the API is not reachable** — the server must be on port 8000; the
  UI dev server proxies `/api` there.
- **OCR reads garbage from a phone photo** — expected at this stage; see
  *What this is, honestly*. Flat scans work far better than photos.

## Tests

```bash
cd server && python -m pytest
```

Extraction and rules are tested directly; the API is tested through
FastAPI's `TestClient` with text uploads, so the suite runs without Tesseract
installed. CI additionally installs Tesseract and exercises the OCR path.
